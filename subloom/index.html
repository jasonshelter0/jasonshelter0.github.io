Subscription management in Obsidian

Subloom reads your Markdown notes, forecasts recurring charges, and keeps confirmed payments separate from expected ones. Your records stay in your vault.

01 / Overview

A clear view of what comes next

Subloom scans subscription notes anywhere in your open vault. It calculates the next scheduled charge from each note’s original billing rule, then shows upcoming charges, payment verification, and known access coverage in one dashboard.

01

Forecast

See weekly, monthly, and yearly charges, plus a monthly estimate grouped by currency.

02

Verify

Record a successful payment only after checking it. Forecasts and auto-renew settings never count as proof.

03

Follow up

Use in-app reminders for approaching charges and payments that still need verification.

Local by design. Subscription data lives in Markdown frontmatter in your vault. Subloom needs no Dataview, Tasks, Reminder, or cloud account.

02 / Setup

Install Subloom 0.1.0

Version 0.1.0 is distributed as a GitHub release. Download the three plugin files from the Subloom 0.1.0 release. Subloom is not yet listed in Obsidian’s Community Plugins directory.

  1. In your vault, create .obsidian/plugins/subloom/.
  2. Place main.js, manifest.json, and styles.css together in that folder.
  3. Reload Obsidian. In Settings → Community plugins, enable Subloom. If needed, first turn off Restricted mode.
  4. Open the dashboard with the calendar-clock ribbon icon or the command Open Subscription Dashboard.
Vault folder

Subloom’s manifest declares a minimum Obsidian version of 1.12.0. For a safe first look, try the fictional demo vault notes in a separate test vault.

03 / First record

Add your first subscription

Run Add Subscription from Obsidian’s command palette or select Add subscription in the dashboard. Subloom creates a starter note in Subloom/ and opens it for editing. You can move subscription notes anywhere in the vault; discovery is not tied to that folder.

  1. Replace the starter service name and set the original subscription_start date.
  2. Set billing_cycle, amount, and currency to match the actual plan.
  3. If applicable, link a payment method note and adjust remind_before.
  4. Open the dashboard to review the forecast. Record a payment only after you verify the charge.

04 / Markdown records

Subscription notes

A note is recognized when it has record_type: subscription, or an exact subscription or subscription/… tag while tag recognition is enabled. A different explicit record_type excludes the note. Valid subscription_start and billing_cycle fields are needed for a forecast.

Example · AI Service.md
---
tags:
  - subscription/ai
record_type: subscription
service: Example AI Service
category: Software
subscription_start: 2026-01-31
billing_cycle: monthly
billing_interval: 1
amount: 20
currency: USD
auto_renew: true
payment_method: "[[Example Card]]"
remind_before: 3
subscription_lifecycle: active
---

Details about this subscription can go here.

Dates use YYYY-MM-DD. For monthly and yearly plans, an anchor day beyond the end of a month is clamped to its last day. For example, a monthly plan anchored on the 31st is forecast on February’s last day. Subloom calculates future dates from the original anchor; it does not roll the start date forward in your note.

The auto_renew field describes your renewal setting. It does not say whether a charge succeeded. Use subscription_lifecycle: paused, cancelled, or archived to keep a record without active charge reminders.

05 / Connections

Payment method notes

Create a separate Markdown note with record_type: payment_method, then point a subscription’s payment_method field to it with a quoted wikilink or note path. A path-qualified wikilink helps when several notes share the same name.

Example · Example Card.md
---
record_type: payment_method
institution: Example Bank
payment_kind: credit_card
currency: USD
card_last4: "1234"
card_expiry_month: 2028-07
payment_method_status: active
---

The dashboard shows linked subscriptions under each payment method. It also adds an attention item when a valid card_expiry_month is within the current or next two calendar months.

Keep secrets out of notes. Store only display information such as the last four digits. Do not put full card numbers, CVV, PINs, passwords, or bank credentials in a payment method note.

06 / Daily use

Use the dashboard

The top of the dashboard shows the active subscription count, charges due within each record’s reminder window, overdue payment checks, and a monthly forecast. Amounts are grouped by currency; Subloom does not convert between currencies. Weekly estimates use 52 weeks per year, and yearly plans are spread across 12 months.

Needs attention lists advance and due-today reminders, unverified past charges, and near-expiring payment methods. Each item can be opened, snoozed for one day, or acknowledged. Upcoming shows the next eight active subscriptions with valid schedules.

All subscriptions includes both active and inactive records. Search by service, path, or category; filter by lifecycle, category, renewal setting, or linked payment method; then sort by next charge, name, or amount. Open a note to edit its fields, or use the card’s Record payment, Pause, and Resume actions. Pause and Resume ask for confirmation and update the original note.

Cards show schedule, verification, and access status separately. A note with incomplete or invalid schedule fields still appears in the list with a field issue, but it has no next-charge forecast until corrected.

07 / Verification

Record a verified payment

After confirming a successful charge, select Record payment on the subscription card. You can also open the subscription note and run the Record Payment command. The dialog asks for the verified payment date and the first day without coverage. Review both dates before selecting Confirm verified payment.

Subloom writes last_payment_date, paid_through, and verification_status: confirmed to the original note. The status shown in the dashboard is computed from whether the verified date falls within the latest scheduled billing cycle; the confirmed text alone does not establish a successful charge.

Example · coverage through November 29
last_payment_date: 2026-10-30
paid_through: 2026-11-30
verification_status: confirmed

paid_through is exclusive: coverage in this example ends at the start of November 30 in local time. Without paid_through, access status is unknown. A future value shows covered; today or an earlier value shows ended. This model does not account for grace periods.

Forecast ≠ payment. A due date and auto_renew: true are expectations. They never create a verified payment or imply current access.

08 / Follow-up

Reminders and notices

Active subscriptions can generate an advance reminder within remind_before days of the next charge, a due-today reminder, and a verification reminder after a scheduled charge has passed without a matching confirmed payment. The dashboard also shows near-expiring payment methods.

The dashboard’s Snooze 1 day action hides an item until the next local calendar day. Acknowledge hides that specific event. A later billing cycle gets a new event. Reminder state is saved in the plugin’s settings data.

Subloom’s notices are Obsidian in-app notices, shown only while Obsidian is open. They are not device push notifications or background alarms. Turn them on or off in Settings → Subloom → In-app notices. The Recognize subscription tags setting controls discovery of tagged notes without an explicit record type.

10 / Help

Troubleshooting and limits

A note is missing from the dashboard

Check that it is a Markdown note with YAML frontmatter and record_type: subscription, or a matching subscription tag with tag recognition enabled. A different explicit record_type prevents tag-based discovery. Subloom reads the currently open vault.

A next charge is missing

Check the dashboard’s field issue on that card. Use a valid YYYY-MM-DD start date, a supported billing cycle, and a positive whole-number interval. The dashboard can still list a record whose schedule is incomplete.

A payment method link has an issue

Make sure the destination note has record_type: payment_method. If multiple notes share the same name, use a path-qualified wikilink, such as "[[Finance/Cards/Example Card]]".

A payment says “unverified” after recording it

Check that last_payment_date falls within the latest scheduled billing cycle. Also review subscription_start and the billing rule. A saved verification_status: confirmed does not override this date check.

No notice arrived while Obsidian was closed

Subloom has no background service. Reopen Obsidian to see in-app notices and the current dashboard. Notices may also be disabled in Subloom settings.

Current scope. Subloom models one recurring rule and the latest verified payment per subscription. It does not store a transaction ledger, infer payment from a forecast, convert currencies, or encode grace periods. The legacy expires field is not treated as verified access.
